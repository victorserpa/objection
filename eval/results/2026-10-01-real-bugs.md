# Fifteen more real bugs (2026-10-01)

Fifteen regressions added to [`eval/real/cases.jsonl`](../real/cases.jsonl),
from nushell (2), helix, netty (2), Prometheus (2), Gitea, Node.js, Vite,
Symfony (2), Npgsql, Rack and Werkzeug: Rust, Java, Go, JavaScript, PHP,
C#, Ruby and Python. Each is a commit whose fix names it as the cause.
Sonnet at effort medium, 4 runs per side: objection 0.23.1 (`bash
eval/run.sh`) against the same model with a plain "review this diff"
prompt and the raw diff (`EVAL_BASELINE=1`).

## What it says

- **Severity**: objection under-rated helix (a new file cannot be saved:
  MEDIUM four times, the plain prompt HIGH four times), as it did Redis
  in the first nine. The accuser's rubric reads more conservative than
  the plain prompt's.
- **Misses the plain prompt did not have**: node (3 of 4 for the plain
  prompt, 0 for objection) and symfony-1942d67 (1 against 0). In both,
  objection's findings were about other lines of the same function.
- **Misses both had**: five cases nobody found at any severity. Two need
  code outside the diff (Prometheus, Vite); three are behavior a reviewer
  has to imagine (nushell, netty responses).
- The sample is still small: 4 runs of 15 cases, one model, one effort.
  It does not say objection is worse in general; it says the first nine
  overstated how much better it is.

## Scoring

The automatic scorer read 33 of 60 for objection and 39 of 60 for the
plain prompt, more than the hand count on both sides: a finding that
cites a bug line counts even when it describes another defect on that
line (netty-3c06dd6, nushell-0a0475e), and a plain-prompt finding with
no `file:line` (node, "QueryString.escape, ~line 89") was missed. The
numbers above are the hand count.

Two scoring changes came with this run:

- A shortened path counts (`buffer/.../AdaptivePoolingAllocator.java:1375`,
  `HttpObjectDecoder.java:951`) when its directories are in the real
  path, in order. A real catch at the bug line scored MISSED before.
- werkzeug-6650f6c covers both defects of its culprit: the crash
  (`server_name` is None) was fixed by a commit that does not name the
  culprit, the doubled port by one that does. Scoring only the second
  had marked eight runs that found the crash as misses.

## A severity rubric, measured the same day

The accuser's prompt had no definition of the severities, and it said a
BLOCKER or HIGH "on `read` alone gets disputed", which reads as "rate
lower when you only read". It now defines each severity by impact and
says confidence goes in the evidence column, not in the severity. Same
setup, four runs, hand-graded on the fifteen:

| | right severity | found |
|---|---|---|
| objection, old prompt | 25 of 60 | 33 of 60 |
| objection, new prompt | 26 of 60 | 35 of 60 |
| plain prompt | 33 of 60 | 37 of 60 |

Within noise on the fifteen: helix went from MEDIUM four times to HIGH
once. On the first nine, Redis's null-pointer crash went from MEDIUM
every time to HIGH in all four runs. The planted and clean cases, two
runs: 71 of 72 as expected, and no false alarm on the 8 clean changes
(16 reviews). The gap to the plain prompt is not severity: it found
bugs objection did not (node, symfony-1942d67) and still does.
